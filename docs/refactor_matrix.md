## 旧版一比一还原准则（长期约束）

旧项目是本工程 UI 层、交互层和功能覆盖范围的唯一基准。每项重构必须先在旧项目中定位对应页面、子组件、资源、文案、数据状态与交互分支，再开始实现；不得根据接口数据流、通用组件、设计习惯或主观猜想“补齐”界面。

- 必须逐项保留旧版的文字、字体、颜色、尺寸、间距、圆角、图标、图片、动效、弹窗、加载/空/错误/未登录/无权限状态，以及点击、滑动、返回、刷新、分页和重复提交等可达功能。
- 不得因新架构、实现成本或暂未使用的数据字段而删除、合并、简化或以新样式替代旧版元素和功能。
- 每次改动应以旧页面/组件为对照完成视觉与交互核验；若旧实现、素材或规则无法确认，必须继续查找旧项目或向用户说明，不得自行假设一种“合理”的方案。
- 允许重新设计代码架构、状态管理与资源生命周期，但最终用户可见的 UI 层与业务行为必须与旧版一致；必要的兼容性替换须明确记录原因及保留的等效行为。

当前 API 基础层已接入启动、认证和当前用户资料接口；业务模块接口将在对应页面重构时逐项接入。

启动模块已按旧版 `SplashPage` 与 `SplashController` 还原：启动页保持白色安全区内的空白可点击容器；已有 `appConfig` 缓存时立即进入首页，同时后台更新线路和配置；首次启动等待线路及配置成功后进入首页；所有候选线路失败时仅显示旧版“线路选择失败，请前往官网”轻提示。旧版“本站全新升级”弹窗实际由首页 `RouteMainController` 在进入首页后请求版本接口触发，因此保留在 home 模块后续迁移，不归入 splash。

开发环境的线路、签名及解密参数保存在工作区外，通过 `--dart-define-from-file` 注入；启动选线失败时停留在启动错误页，不再进入首页触发无效并发请求。

VS Code 与 Android Studio 均已配置本机参数入口；配置属于编译期数据，变更后必须结束旧调试进程并重新运行。

首页阶段已重建主导航壳、动态频道、轮播、推荐排序、分页与下拉刷新；内容详情跳转仍按矩阵随对应模块继续迁移。

根据实际操作反馈，发布动态页右上角“发布”按钮从旧版紧凑文字块扩大为 56×32 的可点击区域，文字同步调整为 14；其余导航栏尺寸不变。富文本编辑器增加页面级点击边界检测，点击编辑器以外区域会同时执行 Summernote 正文 `blur`、原生 WebView `clearFocus` 和键盘收起；监听系统窗口 inset，在用户通过系统收起键盘时也执行相同失焦流程，避免光标仍停留在正文输入区。

`html_editor_enhanced` 间接依赖的 `flutter_keyboard_visibility 6.0.0` 仍将 Android 插件固定编译为 API 31；项目不替换该插件，在根 Gradle 配置中仅把这个插件模块的 `compileSdk` 对齐到当前应用的 API 36，以满足其 AndroidX 依赖的 AAR 元数据要求。该调整不改变目标版本、最低系统版本或运行时行为。
